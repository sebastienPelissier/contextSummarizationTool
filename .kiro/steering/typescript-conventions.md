# TypeScript Conventions — mcp-context-manager

This project is a local MCP server (stdio) for AI session context management.
Always follow these rules consistently.

## Project context

The server exposes 5 MCP tools to manage the context window of AI assistants:
`estimate_tokens`, `summarize_context`, `suggest_cleanup`, `export_summary`, `load_session`.

All processing is **local**: no external LLM, no network, heuristics and regex only.
The server must work **offline** and never crash — it always returns a valid MCP response.

## Language and version

- Strict TypeScript required, Node.js 24+
- `strict: true` in `tsconfig.json` — no exceptions
- No `any`: use `unknown` if the type is truly unknown, then narrow with a type guard

## Runtime and allowed libraries

- `@modelcontextprotocol/server` for the MCP protocol — SDK v2 (renamed from v1)
- `zod/v4` for input validation — import via `import * as z from 'zod/v4'`
- `node:fs/promises` for reading/writing session files
- `node:path` for path construction
- `node:os` for current directory if needed
- **No** network dependency: no fetch, no axios, no HTTP calls

## Required SDK v2 imports

```typescript
import { McpServer } from '@modelcontextprotocol/server';
import { serveStdio } from '@modelcontextprotocol/server/stdio';
import * as z from 'zod/v4';
```

**Never** use `@modelcontextprotocol/sdk` (v1, deprecated).
**Never** use `StdioServerTransport` directly — use `serveStdio(createServer)`.

Tool registration pattern:
```typescript
server.registerTool(
  'tool_name',
  {
    description: 'Tool description',
    inputSchema: z.object({ field: z.string() })
  },
  async ({ field }) => ({
    content: [{ type: 'text', text: result }]
  })
);
```

**stdout = protocol channel** — use `console.error()` for logs, never `console.log()`.

## Code style

- Max line length: 100 characters
- Naming: `camelCase` functions/variables, `PascalCase` classes and interfaces, `SCREAMING_SNAKE_CASE` constants
- Prefer `interface` over `type` for data objects, `type` for unions/aliases
- JSDoc comments in English on all exported functions

Well-formed function example:

```typescript
/**
 * Estimates the number of tokens in a text using the chars/4 heuristic.
 * Accuracy ±15% compared to real GPT/Claude tokenizers.
 */
export function estimateTokens(text: string): number {
  if (text.length === 0) return 0;
  return Math.ceil(text.length / 4);
}
```

## Context thresholds (field-tested)

These thresholds come from the `document-and-clear` Skill and are the project reference:

```typescript
const CONTEXT_THRESHOLDS = {
  WARNING: 0.60,   // 60% — recommend summarize_context + export_summary
  CRITICAL: 0.90,  // 90% — immediate export recommended before context loss
} as const;
```

Never modify these thresholds without a documented reason.

## Exported session file structure

Files generated by `export_summary` follow this format:
- Directory: `./context-summaries/` (create if absent with `fs.mkdir({ recursive: true })`)
- Naming: `session-YYYY-MM-DD-<subject>.md` — subject in kebab-case ASCII, 5 words max
- Anti-overwrite: if file exists, suffix with `-2`, `-3`, etc.
- Encoding: UTF-8 required

The generated Markdown must contain these mandatory sections:
```markdown
## Main Objective
## Decisions Made
## Modified Files
## Next Steps
## Warnings
## Resume Here
```

The `## Resume Here` section contains the suggested first prompt for the next session —
it is the most critical section for context resumption.

## Error handling in MCP tools

The server must **never** crash. Each tool handles its errors internally:

```typescript
// Pattern to follow in each tool handler
try {
  // tool logic
} catch (error) {
  console.error('[tool-name]', error);
  return {
    content: [{ type: 'text', text: `Error: ${error instanceof Error ? error.message : String(error)}` }],
    isError: true,
  };
}
```

- Always log with `console.error()` before returning an MCP error
- Never propagate an unhandled exception outside a tool handler
- Filesystem operations that fail return a clean MCP error, not a Node exception

## Tests

- One test file per tool: `src/tools/*.test.ts` + `src/utils/tokenizer.test.ts`
- Framework: `vitest`
- No filesystem mocking: use `node:os` `tmpdir()` + `afterEach` cleanup
- Every exported function has at least one test
- Required edge cases: empty text, missing directory, existing file (anti-overwrite)

Well-formed test example:

```typescript
import { describe, it, expect, afterEach } from 'vitest';
import { mkdtemp, rm } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { join } from 'node:path';

describe('exportSummary', () => {
  let tmpDir: string;

  afterEach(async () => {
    if (tmpDir) await rm(tmpDir, { recursive: true, force: true });
  });

  it('creates the file with the correct naming', async () => {
    tmpDir = await mkdtemp(join(tmpdir(), 'mcp-test-'));
    // ...
  });
});
```
